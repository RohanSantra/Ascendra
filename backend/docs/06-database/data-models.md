## Reading a schema

For exact field types, nested fields, defaults, enums, validation, immutable paths, `select: false`, timestamps, version-key behavior, and custom validators, open the model file linked in the inventory. A top-level path can itself contain a nested schema or an array of subdocuments.

## Model ownership

Most models live with their business module. `Session` is under `src/modules/sessions/`, while token and user models are under `src/modules/auth/`. `MatchRun` is separated from the matching execution module because it is a persisted historical record.

## Naming and collection behavior

Mongoose derives collection names from model names unless a schema/model explicitly overrides that behavior. This reference does not claim collection names where they are not explicitly configured. Use the Mongoose model configuration and database inspection when exact physical collection naming is required.
